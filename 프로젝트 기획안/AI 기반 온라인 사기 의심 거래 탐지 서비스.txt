AI 기반 온라인 사기 거래 탐지 서비스

1. 프로젝트 개요
프로젝트명: 거래의 신 (Transaction God)

한 줄 소개: AI 기반 중고거래 사기 분석 및 분쟁 중재 올인원 어시스턴트

프로젝트 비전: 누구나 안심하고 중고거래를 할 수 있는 투명하고 신뢰도 높은 거래 환경 조성

핵심 목표:

사전 예방: AI 다중 분석을 통해 잠재적 사기 거래를 90% 이상 필터링

사용자 경험: 거래 전, 단 몇 초 만에 종합적인 위험도 리포트를 제공하여 심리적 안정감 극대화

플랫폼 신뢰도 향상: 데이터 기반의 객관적인 신뢰도 지표를 생성하여 건강한 거래 생태계에 기여

대상 사용자:

주요 타겟: 중고거래 플랫폼(당근마켓, 번개장터, 중고나라 등)을 이용하는 모든 개인 사용자

확장 타겟: 플랫폼 운영자, 보안 기업, 전자상거래 솔루션 제공 업체

2. 배경 및 문제 정의
문제의 심각성: 중고거래 사기 피해 급증

통계 자료: "중고거래 사기 피해 3년간 9만 건 넘어… 피해액 250억 원" [서울신문, 2023.08]

주요 수법: '같은 물건 반복 게시', '시세보다 지나치게 낮은 가격', '메신저 유도 후 선입금 요청' 등 수법이 날로 고도화되고 있음.

근본적인 문제: 주관적 판단의 한계

사용자는 판매자의 프로필, 거래 후기 등 제한된 정보에 의존해 신뢰 여부를 주관적으로 판단해야 하는 상황.

이는 심리적 불안감을 야기하고, 결국 사기 피해로 이어지는 핵심 원인.

따라서, 다양한 데이터를 종합적으로 분석하는 AI 기반 자동 위험도 분석 시스템의 필요성이 절실히 대두됨.

타겟 페르소나 (Persona):

대학생 김민준 (23세): 고가의 중고 맥북을 구매하려 하지만, 큰 금액이라 사기당할까 봐 불안하다. 판매자의 과거 거래 내역만으로는 신뢰하기 어렵다. "이 사람이 올린 제품 사진이 진짜 본인 것일까?", "채팅 말투가 어딘가 찝찝한데..." 와 같은 고민을 한다.

주부 박서연 (35세): 육아용품을 중고로 자주 거래하지만, 비상식적인 거래 조건을 제시하는 판매자를 만날까 봐 걱정된다. "시세보다 너무 싼데, 혹시 문제가 있는 제품은 아닐까?" 하는 의심이 든다.

3. 핵심 기능 및 구현 방식
🔑 5대 핵심 분석 모듈
분석 모듈

설명

핵심 기술 및 구현 방식

1. 채팅 NLP 분석

사기 유도성 대화 패턴 감지

KoBERT 기반 Fine-tuning 모델을 활용. "선입금 해주시면 바로 보내드릴게요", "카톡으로 넘어와서 얘기하죠" 등 사기 의심 문장을 실시간으로 탐지.

2. 이미지 도용/중복 감지

사기에 사용된 이미지 재사용 여부 확인

CLIP 모델을 활용하여 업로드된 이미지와 기존 사기 DB 이미지 간의 의미적/시각적 유사도를 측정.

3. 위치/가격 이상 탐지

시세에 맞지 않는 비정상적인 가격/위치 정보 분석

MySQL에 구축된 지역별/카테고리별 평균 시세 데이터와 비교. Redis로 시세 정보를 캐싱하여 응답 속도 최적화.

4. 판매자 평판 시각화

판매자의 과거 이력을 종합 분석

거래 이력, 신고 접수 이력, 플랫폼 평점 등 비정형/정형 데이터를 종합하여 신뢰도 지표 생성. Chart.js로 시각화.

5. 통합 위험도 스코어링

모든 분석 결과를 종합한 최종 위험도 제공

각 분석 모듈의 결과를 가중치 모델로 종합하여 0~100점의 직관적인 스코어 산출. 위험도에 따라 색상 경고(초록/노랑/빨강) 제공.

⚙️ 기능별 상세 구현 방안
1. 채팅 NLP 분석
User Story: "대학생 김민준으로서, 나는 판매자와의 채팅 내용을 입력해 사기 위험도를 점수로 확인하고 싶다. 그래야 큰 돈을 안심하고 보낼 수 있다."

구현 방식:

[Frontend] 사용자가 React 앱의 텍스트 입력창에 채팅 내용을 붙여넣는다.

[Backend] REST API 요청을 통해 채팅 텍스트가 Spring Boot (Analysis-Service)로 전송된다.

[AI] Analysis-Service는 Python으로 구현된 AI-Serving API를 호출. AI-Serving은 AI Hub의 사기/스팸 데이터로 Fine-tuning된 KoBERT 모델을 통해 텍스트의 사기 확률을 예측.

[Response] 예측 결과(사기 확률, 위험 키워드)가 JSON 형태로 반환되어 사용자 화면에 표시된다.

2. 이미지 도용/중복 감지
User Story: "이 판매자가 올린 제품 사진이 인터넷에서 퍼온 도용 사진은 아닌지 확인하고 싶다."

구현 방식:

[Frontend] 사용자가 React 앱에서 분석하고 싶은 상품 이미지를 업로드한다.

[Backend] 이미지는 Spring Boot를 통해 Azure Blob Storage에 임시 저장되고, 이미지 경로가 Analysis-Service로 전달된다.

[AI & DB] Analysis-Service는 AI-Serving API를 호출.

1차: AI-Serving은 CLIP 모델을 이용해 업로드된 이미지의 벡터값을 추출하고, MongoDB에 저장된 기존 사기 이미지 벡터 DB와 코사인 유사도를 측정.

2차 (선택): Google Reverse Image Search 같은 외부 API를 연동하여 웹 전반의 이미지 중복 여부를 교차 검증.

[Response] 유사도가 높은 이미지가 발견되면 '이미지 도용 의심' 경고를 반환한다.

3. 위치/가격 이상 탐지
User Story: "이 상품, 시세보다 너무 싼데 혹시 허위 매물은 아닐까?"

구현 방식:

[Data] MySQL에 카테고리별/지역별 평균 시세 테이블을 주기적으로 업데이트하며 구축.

[Backend] 사용자가 상품 가격/위치 정보를 입력하면, Analysis-Service는 이를 **비동기 Task(예: @Async)**로 분리하여 처리.

[Cache] 먼저 Redis 캐시에서 해당 지역/카테고리의 시세 정보를 조회. Cache Miss 발생 시 MySQL에서 조회 후 Redis에 저장하여 응답 시간 최소화.

[Logic] 조회된 평균 시세와 ±30% 이상 차이가 날 경우 '가격 이상' 플래그를 활성화한다.

4. 판매자 평판 시각화 및 통합 위험도 스코어
User Story: "이 판매자의 과거는 어땠을까? 종합적인 신뢰도를 한눈에 보고 싶다."

구현 방식:

[Data] 판매자의 거래 이력, 신고 내역 등 비정형 로그는 MongoDB에, 평점 등 정형 데이터는 MySQL에 저장/관리.

[Backend] Analysis-Service는 각 분석 모듈(NLP, 이미지, 가격, 평판)에서 반환된 위험 점수들을 미리 정의된 가중치 모델에 따라 합산하여 최종 위험도 스코어(0~100)를 산출.

[Frontend] React 대시보드에서 최종 스코어를 수신. Chart.js를 이용해 판매자 평판 데이터를 시각화하고, 스코어에 따라 직관적인 색상 경고(초록/노랑/빨강)와 상세 경고 메시지를 함께 제공.

4. 시스템 아키텍처 및 데이터 흐름
핵심 데이터 흐름 (종합 분석 요청 시):

[Client] 사용자가 React 앱에서 판매자 정보(게시글 URL, 채팅 내용, 이미지 등)를 입력하고 '종합 분석 요청'.

[Gateway] Azure API Gateway가 JWT 토큰을 검증하고 요청을 Analysis-Service로 라우팅.

[Backend-Orchestration] Analysis-Service는 요청을 받아 각 분석 모듈(NLP, 이미지, 가격 등)에 해당하는 로직을 비동기적으로 병렬 호출.

[AI & DB] 각 모듈은 AI-Serving, MySQL, MongoDB, Redis 등과 통신하여 개별 분석을 수행.

[Scoring] Analysis-Service는 모든 비동기 작업의 결과를 취합하여 최종 위험도 스코어를 계산하고, 결과를 DB에 저장.

[Response] 계산된 최종 리포트가 Frontend로 전송되어 사용자에게 시각화된 대시보드로 제공됨.

5. 기술 스택
영역

기술

백엔드

Spring Boot, Spring Security, JPA, REST API, MSA 구조 (Gateway / Service 분리)

데이터베이스

MySQL (구조화 정보), MongoDB (비정형 이미지/로그), Redis (세션/캐싱)

프론트엔드

React.js, TailwindCSS, Chart.js, Zustand (상태관리)

인공지능

KoBERT (사기 채팅 분류), CLIP (이미지 유사도 분석), AI Hub 학습 데이터셋 활용

배포/운영

Microsoft Azure (App Service, PostgreSQL Server, Blob Storage, ML), Docker, CI/CD Pipeline

기타

OAuth2 로그인 (Google/Kakao), 더치트 API 연동 (신고 이력 조회)

7. 기대효과 및 사업 확장성
기대효과:

사기 피해 감소: 거래 전 구체적인 위험 경고를 통해 사용자의 금전적/정신적 피해를 직접적으로 감소.

심리적 안심감 제공: 'AI가 한번 검증했다'는 사실만으로 사용자의 거래 불안감을 크게 해소.

플랫폼 신뢰도 향상: 깨끗한 거래 환경 조성에 기여하여 플랫폼의 전체적인 가치 상승.

사업성과 확장성:

B2B API 연계: 중고거래 플랫폼에 API를 판매하여 'AI 안심 인증'과 같은 유료 부가 서비스로 제공.

B2C 서비스 출시: 일반 사용자를 위한 독립적인 앱 또는 브라우저 확장 프로그램(Extension)으로 출시하여 구독 모델(Freemium) 도입.

이종 산업 제휴: 사기 데이터와 분석 모델을 기반으로 사기 방지 보험사, 전자지갑 앱(토스, 카카오페이) 등과 제휴하여 새로운 금융 보안 상품 개발.
